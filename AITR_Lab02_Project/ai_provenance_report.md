## Part 1: AI-Assisted Activity Log

### 1. Conceptualization & Gap Analysis
*   **Task:** Identify the primary gap in current RAG evaluation literature.
*   **AI Proposal:** The AI generated a comprehensive gap matrix comparing temporal generalization, knowledge conflicts, and RAG architectures.
*   **Human Decision:** I evaluated the matrix and selected the specific intersection of "parametric knowledge cutoff" and "post-cutoff evidence synthesis" (Temporal Friction), discarding the AI's suggestions regarding federated learning and multi-hop chunking as out of scope.
*   **Verification:** Cross-referenced the AI's claims against recent surveys (Gao et al., 2023) to confirm the gap was genuine.

### 2. Experimental Scripting & Execution
*   **Task:** Automate the RAG synthesis and LLM-as-a-Judge pipeline.
*   **Tool:** `google:ds_python_interpreter` 
*   **AI Proposal:** The AI initially drafted Python code using the `google-generativeai` SDK.
*   **AI Limitation & Manual Correction (Real Example 1):** The official SDK's default gRPC transport layer consistently triggered silent, infinite hangs in my local Windows environment, stalling the 300-paper execution without throwing trackable errors. I directed the AI to abandon the SDK entirely and rewrite the pipeline (`src/baseline_1_gemini.py`) using raw `urllib` REST calls with explicit 120-second timeouts. This manual architectural pivot was critical for stability.

### 3. Data Parsing & Robustness
*   **Task:** Extract JSON scoring metrics from the LLM-as-a-Judge output.
*   **AI Limitation & Manual Correction (Real Example 2):** The LLM judge frequently hallucinated conversational fluff around the JSON blocks (e.g., "Here are your scores: { ... }"), causing standard `json.loads()` to crash the loop. I instructed the AI to implement a robust Regex extractor (`re.search(r'\{.*\}', response_text, re.DOTALL)`) and a strict fallback schema returning `None` to ensure the batch processor could gracefully handle these failures without crashing the entire run.

### 4. Statistical Evaluation
*   **Task:** Compute $p$-values for Omission Score and Stale Framing.
*   **AI Limitation & Manual Correction (Real Example 3):** During early testing on small data subsets, the AI's `scipy.stats.kruskal` implementation threw `ValueError: All numbers are identical in kruskal`. The AI did not initially account for zero-variance partitions. I engineered dynamic variance checks (`if len(omission_groups) > 1`) and `try-except` blocks within `scripts/07_evaluation_audit.py` to allow the pipeline to skip invalid tests without failing the visualization execution.

### 5. Manuscript Drafting & Formatting
*   **Task:** Typeset the final manuscript in the ACM Computing Surveys (CSUR) format.
*   **AI Proposal:** Generated the `main.tex` and `references.bib` files, executing Python to zip them together.
*   **Human Decision & Purposeful Verification:** I manually requested the insertion of the `nonacm` flag to suppress distracting boilerplate copyright text for the draft review phase. I also purposefully verified that the cited baseline metrics in the LaTeX text (e.g., $p=0.4057$) precisely matched the outputs generated by the audited CSV results (`scripts/04_generate_paper_results.py`).

## Part 2: Reflective Account of Verified Human Decisions

### Conclusions Dependent on Human Reasoning
While the AI processed the raw data and generated the non-parametric statistics, the interpretation of the "Double Null" result relied entirely on human reasoning. The AI simply reported that the $p$-values (0.4057 and 0.8285) were "not significant." It was my human analysis that framed this lack of significance not as a failure of the experiment, but as empirical proof of an **Absolute Parametric Override**—demonstrating that modern attention mechanisms successfully compartmentalize and suppress outdated long-term memory in favor of retrieved context.

### Insights on "Vibe Coding"
This project highlighted that relying purely on conversational "vibe coding" is insufficient for rigorous academic engineering. The AI writes syntactically correct code, but it lacks environmental awareness (e.g., the Windows gRPC hangs) and defensive programming instincts (e.g., the JSON extraction failures and SciPy variance errors). Generating a working script requires active human steering, architectural decisions, and explicit edge-case handling. 

### Remaining Risks
*   **LLM Judge Subjectivity:** The core metrics (Omission and Stale Framing) rely on an LLM-as-a-Judge. While prompts were tightly constrained, there remains a risk of latent model bias in the grading process.
*   **Context Window Dilution:** The experiment used a batch size of 10 abstracts. The risk remains that the Absolute Parametric Override might degrade if the context window is flooded with 100+ documents (the "Lost in the Middle" phenomenon).
